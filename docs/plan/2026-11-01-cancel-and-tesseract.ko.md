# 취소 즉시 반영과 Tesseract 시도 동시 실행 — 계획과 결과

작성 2026-11-01 · 백로그 P-23, P-27 · 브랜치 `ocr-accuracy-foreign-only` · 기준 커밋 `f7b7d24`

[속도 계획](2026-11-01-ocr-speed.ko.md)에서 남긴 두 가지다. 둘 다 인식 결과를 바꾸지 않고 기다리는 시간만 줄인다.

## 1. 현재 상태

| 항목 | 지금 동작 | 근거 | 문제 |
|---|---|---|---|
| 취소 (P-23) | 취소 신호를 줄·모델 실행 **사이에만** 확인. 실행 중인 검출은 끝까지 돈다 | `paddle_tests` `cancelledReadReleasesTheEngine`: 264ms | 마우스 올려두기에서 위치를 바꾸면 이전 읽기가 끝날 때까지 다음 읽기가 기다림 |
| Tesseract 시도 (P-27) | 원본 → 밝은 글자 마스크 → 두껍게 → 밝기만, 최대 4회를 **차례로**. 시도마다 프로세스를 새로 띄움 | 벤치마크: 베트남어 대사창 중앙값 524ms, 최대 923ms | 베트남어·Tesseract 엔진 설정이 가장 느림. 언어 선택 대사창 p95(478ms)도 이 행들 때문 |

## 2. 목표와 범위

목표: 취소 후 대기를 없애고, Tesseract 시도를 동시에 돌려 기다림을 줄인다. 결과 문자열은 하나도 바뀌지 않아야 한다.

| ID | 바꿀 것 | 종류 | 우선 |
|---|---|---|---|
| C1 | `OcrCancel`: 읽기마다 ONNX Runtime 실행 옵션을 하나 두고, 취소하면 `SetTerminate`로 **실행 중인 모델 계산도** 멈춤 | 보강 | P2 |
| T1 | 원본 이미지 먼저 한 번. 확신이 부족하면 나머지 마스크를 OCR 스레드 예산(논리 프로세서의 1/4, 1–4개)만큼 **동시에** 실행 | 보강 | P2 |

범위 밖과 그 이유:
- **이미지 목록 파일로 Tesseract 한 번만 띄우기**: 프로세스 시작 비용이 줄지만, 화면 이미지를 디스크에 써야 한다. "이미지를 파일로 저장하지 않음" [결정 2026-09-29](DECISIONS.md)과 충돌해서 하지 않는다.
- **Tesseract를 앱 안에 넣기**(라이브러리 링크): 개발 헤더·라이브러리가 없고, 빌드 구성이 크게 바뀐다.

## 3. 설계

- **C1**: `paddle_ocr.h`에 `OcrCancel`(원자 플래그 + 실행 옵션)을 추가한다. `PaddleRecognizer::recognize`, `PaddleDetector::lines`, `PaddleOcr::read`, `countTextLines`가 이것을 받는다. 중단된 검출은 결과가 비므로, 줄 찾기 대체 경로로 넘어가기 전에 취소를 확인한다. `OcrService`는 읽기와 Tesseract 전 검출 확인마다 새 `OcrCancel`을 만든다.
- **T1**: `OcrService`의 Tesseract 프로세스를 여러 개(`jobs_`) 관리한다.
  - 끝난 시도는 `outputs_`에 모아 두고, **이미지 순서대로** 예전과 같은 규칙으로 판정한다(신뢰도 90 이상이면 멈춤, 마스크는 원본보다 5 높아야 채택). 그래서 동시에 돌려도 고르는 판독은 같다.
  - 결정이 나면 남은 프로세스는 종료한다.
  - 동시 실행 수는 `PaddleOcr::threads()`다. 논리 프로세서가 8개 미만인 PC는 1개라 예전처럼 차례로 돈다.
- **메모리 지표**(`peakWorkingSetBytes`): 동시에 도는 프로세스들의 최대 사용량을 **합한** 값으로 바뀐다.
- **정합성**:
  - "게임을 방해하지 않는다"는 지킨다. Tesseract 빌드는 프로세스당 스레드 1개(OpenMP 없음)라서, 동시 실행 수가 곧 사용하는 코어 수다. 이 수는 OCR 스레드 예산과 같다.
  - 오인식 기준(Tesseract 신뢰도 30 미만 버림)은 그대로다.
  - 취소 후 늦게 온 결과를 버리는 세대 번호도 그대로다.

### 개발 중 발견한 것

- 취소된 검출은 빈 결과를 돌려준다. 확인 없이 지나가면 줄 찾기 대체 경로(가장자리 검사)가 큰 이미지를 다시 훑으므로, 검출 직후에 취소를 확인하게 했다.
- 이 Tesseract 빌드에는 OpenMP가 없다(`--version`에 표시 없음). 동시 실행 수가 그대로 사용 코어 수다.
- 마스크 2회만 필요한 이미지는 빨라지지 않는다(361 → 365ms). 원본이 먼저 혼자 돌고, 그 뒤 마스크 하나만 남기 때문이다.

### 아직 확인하지 못한 것

- 논리 프로세서 8개 미만 PC(동시 실행 1개)에서 예전과 같은 시간인지. 코드상 같은 순서다.
- 실제 게임 중 Tesseract 3개 동시 실행의 영향 → P-13.
