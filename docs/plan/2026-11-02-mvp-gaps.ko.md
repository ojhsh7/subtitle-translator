# MVP 사용자 기준 부족한 점 보강 — 계획과 결과

작성 2026-11-02 · 백로그 P-33 · 기준 커밋 `12b6555`

요청: "프로그램을 분석하고, MVP 대상이 썼을 때 부족해 보이는 점을 조사해서 강화."

## 1. 대상과 장면

[기획서 3절](../product-design.ko.md)의 주 사용자는 Windows에서 일본어·영어 비주얼 노벨이나 RPG를 하는 개인이다. 대사창이 화면 아래에 고정되어 있고, 대사는 버튼을 누를 때마다 넘어간다. 이 장면을 처음 설치부터 플레이 30분까지 따라가며 막히는 곳을 찾았다.

### 이 앱으로 따라가 본 결과

| # | 장면 | 지금 | 부족한 점 |
|---|---|---|---|
| G1 | 대사를 빨리 넘김 | 자막은 마지막 한 줄만 남음 | 놓친 대사를 다시 볼 수 없음. 백로그는 위 도구들의 기본 기능 |
| G2 | 인물 이름이 대사마다 다르게 번역됨 (`ユウキ` → 유키 / 유우키) | 고칠 방법 없음 | 이름·용어를 한 가지로 맞출 수 없음. OCR이 늘 같은 글자를 틀리는 경우도 고칠 수 없음 |
| G3 | 일본어 게임과 영어 게임을 번갈아 함 | 영역은 게임별로 기억, 언어는 하나 | 게임을 바꿀 때마다 게임 언어를 다시 골라야 함 |
| G4 | 한 달 내내 자동 번역 | 한도를 넘으면(456) 그때 멈춤 | 남은 양을 설정의 "확인"을 눌러야만 봄. 넘기 전에 알 수 없음 |
| G5 | 처음 설치 | 무대에 "자막 영역을 고르고 자동 번역을 켜면…"만 표시 | 키가 없거나 영역이 없을 때도 같은 문구라 다음에 할 일을 모름 |

## 3. 목표와 범위

| ID | 바꿀 것 | 원칙 확인 |
|---|---|---|
| G1 | **대사 기록 창**: 화면에 나온 최근 200줄(시각·번역·원문)을 아래로 쌓음. 두 번 클릭하면 복사, 모두 지우기. 더 보기·트레이 메뉴에서 열기 | 메모리에만 두고 앱을 닫으면 사라짐. 영구 저장은 하지 않음([기획서 5.4](../product-design.ko.md)) |
| G2 | **고쳐 쓰기**(설정 새 페이지): "번역문에서 / 원문에서 찾을 말 → 바꿀 말" 표. 원문 쪽은 번역 전에, 번역 쪽은 화면에 띄우기 전에 바꿈 | 로컬 처리. 원문을 고치면 DeepL에도 고친 글자가 감. 단순 문자열 바꾸기라 예측 가능 |
| G3 | **게임별 게임 언어**: 게임 창 영역을 고를 때와 언어를 바꿀 때 그 게임에 저장하고, 다른 게임이 앞에 오면 그 게임의 언어로 바꿈 | 기존 게임별 영역 저장과 같은 위치 |
| G4 | **사용량 표시**: 시작 2초 뒤, 설정 저장 뒤, 번역 요청 50번마다 `/v2/usage`(글자 차감 없음)로 확인해 더 보기 메뉴에 "이번 달 n% 사용, 남은 m자" 표시. 90%를 넘으면 상태 줄에 알림 | 키와 전송 동의가 있을 때만. 번역 요청과 따로 된 연결 |
| G5 | **다음 할 일 안내**: 무대가 비어 있을 때 상태에 맞춰 안내(키 없음 → 번역 페이지, 영역 없음 → 영역 선택, 준비됨 → 자동 번역) | 비어 있는 화면은 행동을 안내하는 자리 (frontend-design 원칙) |

범위 밖과 그 이유:
- **DeepL 용어집 API**: 원문 언어를 반드시 지정해야 하고, 계정에 용어집을 만들고 관리해야 한다. G2가 같은 문제를 로컬에서 먼저 푼다 → P-34 보류.
- **기록을 파일로 저장**: 하지 않기로 한 결정(5.4)이 있다.
- **이전 문맥을 넣은 번역**: DeepL `context` 파라미터는 문맥 글자도 보내야 해서 사용량과 전송량이 는다 → 보류.

## 5. 결과

| ID | 결과 |
|---|---|
| G1 | **대사 기록** 창(더 보기·트레이 메뉴): 화면에 나온 최근 200줄을 아래로 쌓는다. 번역 줄 아래에 원문을 두고, 시각은 툴팁으로 보인다. 두 번 클릭하거나 "복사"로 번역을 복사하고, "모두 지우기"로 비운다. OCR만 한 줄(키 없음)도 원문으로 남긴다. 같은 줄을 다시 읽으면 한 줄로 친다. 메모리에만 있다 |
| G2 | 설정 **고쳐 쓰기** 페이지: "어디서(번역문/원문) · 찾을 말 · 바꿀 말" 표. 원문 쪽 수정은 DeepL로 보내기 전에 적용된다(테스트: 요청 본문에 고친 글자만 있음). 번역 쪽 수정은 화면·결과 창·대사 기록에 적용된다. 번역 기억(P-31)에는 고치기 전 번역을 두어 표를 바꾸면 바로 반영된다 |
| G3 | 게임 창 영역을 고를 때와 게임 언어를 바꿀 때 그 게임의 설정 묶음에 언어를 저장한다. 다른 게임이 앞에 오면 그 게임의 언어로 바꾼다 |
| G4 | 시작 2초 뒤, 설정 저장 뒤, 번역 요청 50번마다 `/v2/usage`로 확인해 더 보기 메뉴에 "DeepL 이번 달 n% 사용, m자 남음"을 표시한다. 90% 이상이면 상태 줄에 알린다. 번역과 다른 연결을 쓴다 |
| G5 | 비어 있는 무대의 문구가 상태를 따른다. 키나 동의가 없으면 번역 페이지, 영역이 없으면 영역 선택, 준비되면 자동 번역을 안내한다 |

### 검증

- **CTest**: 7개 그룹 **187 통과**, 실패 0, 건너뜀 0(UI 43). 새 테스트는 다음 세 개다.
  - `backlogAndTextFixes`
  - `eachGameKeepsItsLanguage`
  - `usageAndNextStepGuidance`: 로컬 HTTP가 92%로 답함.
- **테스트 안전장치**: 테스트 실행 중(`testMode`)에는 사용량 확인과 DeepL 미리 연결이 테스트 서버로만 간다. 키를 넣은 테스트가 실제 DeepL에 닿지 않는다.
- **화면**: [고쳐 쓰기 페이지](../evidence/mvp-gaps-2026-11-02/settings-6.png).

### 아직 확인하지 못한 것

- **실제 게임에서의 사용 흐름**: 기록 창을 언제 여는지, 고쳐 쓰기 표가 몇 줄까지 쓸 만한지 → P-13.
- **DeepL 용어집 API**: 고쳐 쓰기로 해결되지 않는 경우(문맥에 따라 다른 번역)가 있는지 → P-34 보류.
