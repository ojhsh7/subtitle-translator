## 1. 현재 상태

## 3. 설계

### 3.1 변화 감지 (`src/change_detector.*`) — E1, E2

지금의 "3픽셀 규칙"은 **완전히 멈춘 화면**을 알아보는 데만 쓰고, 멈추지 않는 화면을 위한 길을 하나 더 둔다.

- **윤곽 지도**: 화면을 "좌우 밝기 차가 큰 픽셀" 지도로 바꾼다. 글자는 윤곽이 강하고, 부드러운 배경 움직임은 윤곽이 거의 없다.
- **변화량 g**: 지금 화면과 마지막으로 읽은 화면의 윤곽 지도가 다른 픽셀의 비율.
- **늘어남**: g가 지금까지의 최고값을 뚜렷이 넘으면 "글자가 늘고 있다"로 본다. 한 글자씩 나오는 줄은 매번 늘고, 화살표나 반짝임은 최고값 아래에서 오르내린다.
- **멈춤 판정**: 0.3초 동안 늘어남이 없으면 줄이 다 나온 것으로 본다. 픽셀이 조금 흔들려도 된다.
- **움직임 허용치**: 읽었더니 글자가 그대로였다면, 그때의 g는 움직임 때문이다. 메인 창이 `noteSameText()`로 알려 주면 허용치를 올리고, g가 허용치 아래면 읽지 않는다. 새 글이 허용치에 가려 늦게 발견되면 허용치를 절반으로 내린다.
- **읽은 화면 기억**: 최근에 읽은 화면 4장을 기억한다. 멈춘 화면이 그중 하나와 같으면 다시 읽지 않는다(깜빡임).
- **안전망**: 계속 바뀌는 화면은 지금처럼 3초마다 한 번 읽는다. 새 방식이 틀려도 지금보다 나빠지지 않는다.

정지 화면에서의 판정 시점(0.15초 감지, 0.3초 대기)은 그대로다.

### 3.2 보내는 시점 (`src/main_window.cpp`) — E3, E4

- 끝나지 않은 줄을 읽으면 글자와 시각을 기억한다(`pendingText_`, `pendingSince_`). 다음에 읽은 글자가 같으면 시각을 유지하고, 다르면 새로 잡는다.
- 화면이 늘어나는 중이 아니고 기억한 글자가 0.8초 그대로면 보낸다. 화면 흔들림만으로는 버리지 않는다.
- 줄이 한 번의 변화로 떴으면(감지기의 `appearedAtOnce()`) 마침표가 없어도 바로 보낸다. 한 글자씩 나오는 게임에서는 쓰지 않는다: 읽은 글이 앞 글에 이어 붙은 것이면 그 게임은 한 글자씩 나오는 것으로 보고 이 지름길을 끈다.
- 추가 영역(P-37)에도 같은 규칙을 쓴다.

### 3.3 같은 줄 판단 — E5, E6

- **기억 키를 다듬는다**: 공백을 지우고, 끝에 붙은 넘김 표시(▼▽▾↓ 등)를 뗀 글로 번역을 기억한다(최근 200줄, 메모리에만).
- **닮은 줄 예산**: 화면에 떠 있는 줄과 거의 같은 글(8자 이상, 다른 글자가 길이의 1/8 이하)이 새로 읽히면 오독일 수 있다. 줄마다 2번까지는 새로 번역하고, 그 뒤로는 떠 있는 번역을 그대로 쓴다. 진짜로 한 글자만 바뀐 줄은 첫 번째에 번역되므로 놓치지 않고, 오독이 계속 바뀌어도 낭비는 줄당 2번에서 멈춘다.
- **앞부분 재사용**: 새 글이 이미 번역한 글로 시작하면 뒷부분만 보내고, 앞 번역 뒤에 이어 붙인다. 앞부분은 DeepL `context`로 넘긴다(요금 없음).

### 3.4 보호와 표시 — E7, E8, E9

- **폭주 차단**: 자동 번역에서 30초 안에 20번을 넘게 보내려 하면 20초 동안 원문만 보여 주고 상태 줄에 알린다.
- **세션 집계**: 보낸 요청·글자 수, 기억으로 아낀 글자 수를 세어 설정의 번역 페이지와 문제 보고서에 보여 준다. 글자 내용은 남기지 않는다.
- **연결 유지**: 자동 번역 중 게임 창이 보이면 15초마다 연결을 다시 열어 둔다. 요청을 보내지 않으므로 한도를 쓰지 않는다.

### 3.5 기존 결정과의 관계

- "유료 API 실패는 여기서 재시도하지 않는다"(ChangeDetector 주석): 그대로다. 새로 생기는 읽기는 모두 OCR이고, 요청은 오히려 줄어든다.
- P-31의 0.15초 감지·0.3초 대기·0.8초 문장 대기: 값은 그대로이고, "멈춤"의 뜻만 픽셀에서 글자 늘어남으로 넓힌다.
- 감지기 테스트 중 "움직이는 배경은 3초마다 읽는다" 두 개는 새 동작(처음 한 번 읽고, 글자가 같으면 더 읽지 않는다)에 맞게 고친다.

## 6. 결과

**움직이는 화면에서도 줄이 다 나온 뒤 0.4~0.6초에 자막이 뜨고, 모든 화면에서 한 줄에 요청이 한 번만 나간다.** 전에는 마침표 없는 줄이 움직이는 화면에서 아예 번역되지 않았고, 움직이는 화면의 자막은 2~3초 늦었다.

환경: 같은 PC, Release 빌드, PaddleOCR(일본어), 로컬 가짜 번역 서버. 측정은 `tests/scene_probe.cpp`(대사 4줄, 줄마다 4초, 반짝임은 6초). 수정 전은 기준 커밋 `7441f57`을 같은 도구로 잰 값이다. 수정 전 첫 측정은 정지 화면도 4줄 중 1줄만 번역되는 등 다시 재면 나오지 않는 값이 섞여 있어서, 두 번째 측정을 기준으로 삼았다.

### 6.4 설계와 달라진 점

- **닮은 줄 예산(3.3)**: "줄당 2번까지 새로 번역"하는 방식 대신 "두 번째 읽기가 같을 때만 번역"으로 바꿨다. 오독이 한 번 섞이면 요청이 0번이고, 진짜 바뀐 글은 0.4초 늦게 번역된다.
- **폭주 차단(3.4)**: 20번 → 30번. 1.5초마다 넘어가는 빠른 자동 진행도 걸리지 않게 했다. 사람이 읽을 수 있는 속도(초당 1줄)보다 빠르면 걸린다.
- **감지 주기**: 계획에는 없었다. 0.15초 감지·0.3초 대기(P-31)를 화면이 바뀌는 동안만 0.075초·0.225초로 줄였다. 평소에는 0.15초라 정지 화면의 CPU는 그대로다.
- **기억한 번역**: 고쳐 쓰기를 적용하기 전 번역을 기억하고 보여 줄 때 적용한다. 나중에 더한 고쳐 쓰기도 기억한 줄에 쓰인다. 번역 언어나 게임 언어를 바꾸면 화면 줄 기억을 지워서, 앞부분 재사용이 예전 언어 번역에 붙지 않는다.

### 6.5 개발 중 발견한 것

- **마침표 없는 줄이 영영 번역되지 않던 원인**: 끝나지 않은 줄을 기다리는 동안 화면이 조금이라도 바뀌면 그 줄을 버렸다. 깜빡이는 화살표가 0.45초마다 화면을 바꿔서 0.8초 대기가 끝나지 않았다.
- **깜빡임에서 읽기가 많던 원인**: 마지막으로 읽은 화면 한 장만 기억해서, 켜짐·꺼짐 화면이 번갈아 "새 화면"이 됐다. 20초에 34번 읽었다(CPU 38.9%).
- **움직이는 화면에서 2~3초 늦던 원인**: 3픽셀만 달라도 "바뀌는 중"으로 봐서, 3초 강제 읽기까지 기다렸다.
- 움직이는 화면의 CPU는 3초마다 하는 확인 읽기가 대부분이었다(읽기 한 번 75ms 중 줄 찾기 65ms). 지난 줄 위치만 다시 읽게 해서(P-39) 기존 코드보다 낮아졌다.
- **확인 읽기의 함정**: 확인 읽기에서 오독이 나온 뒤 같은 사진을 전체 읽기로 다시 읽으면 같은 오독이 나와, "두 번째 읽기도 같다"로 잘못 확인했다(반짝임 화면에서 요청 4 → 6번). 오독 확인은 반드시 다음 화면으로 한다.
- 첫 줄은 비교할 "화면의 대사"가 없어서 닮은 줄 규칙이 쓰이지 않는다. 그래서 글자 확신도로 오독을 걸렀다(E11). 반짝임 화면 6번 측정에서 모두 요청 = 줄 수.

### 6.6 아직 확인하지 못한 것

- **실제 게임**: 가짜 게임 화면으로만 쟀다. 실제 게임 글꼴에서 OCR이 화살표를 글자로 읽는 경우, 대사창이 반투명한 경우 → P-13.
- **실제 DeepL**: 한도를 쓰지 않으려고 로컬 가짜 서버로만 쟀다. 실제 왕복 0.25초(P-31 측정)가 위 시간에 더해진다.
- **확신도 기준 0.9**: 가짜 게임(Yu Gothic 굵은 글씨)에서 정한 값이다. 실제 게임 글꼴이 늘 0.9 아래로 읽히면, 움직이는 화면의 첫 읽기마다 0.4초씩 늦어진다(요청은 늘지 않는다) → P-13에서 확인.
- **흐리게 읽힌 글·확인 읽기의 UI 테스트**: 확신도가 낮은 읽기를 테스트에서 일정하게 만들 방법이 없어 측정(반짝임 화면 6번)으로만 확인했다.
