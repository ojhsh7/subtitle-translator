## 2. 보강 목표와 범위

목표: 게임을 하는 중에 메인 창을 열지 않고도 영역을 정하고, 한 번 정한 영역은 게임 창을 옮겨도 유지되게 한다. 마우스 번역은 읽은 범위를 눈으로 확인할 수 있게 한다.

| ID | 기능 | 종류 | 우선 |
|---|---|---|---|
| F1 | **게임 창 따라가기**: 영역을 고를 때 그 아래 게임 창을 기억하고, 창 이동·크기 변경·모니터 이동을 따라 영역을 다시 계산한다. 게임이 최소화되면 자동 번역을 끄지 않고 기다린다 | 신규 (기존 모듈 연결) | P0 |
| F2 | **게임별 영역 기억**: 게임마다 영역을 따로 저장하고, 앞에 있는 게임의 영역을 자동으로 쓴다 | 신규 | P0 |
| F3 | **영역 지정 단축키** Ctrl+Alt+R (사용 중이면 F7): 마우스가 있는 모니터에서 바로 영역 선택 화면을 연다 | 신규 | P1 |
| F4 | **영역 선택 화면 개선**: 드래그 중 크기 표시, 현재 영역 점선 표시, 방향키로 현재 영역 이동(Shift 10px), Ctrl+방향키로 크기 조절, Enter로 확정 | 보강 | P1 |
| F5 | **읽은 범위 표시**: 마우스 번역·올려두기·Ctrl+Alt+T가 캡처한 사각형을 0.6초 동안 테두리로 보여 준다. 클릭은 통과하고 다음 캡처에 들어가지 않는다 | 신규 | P1 |
| F6 | 올려두기 이동 직후 재요청 지연(R-02) 측정 | 검증 | P2 (이번에는 계획만) |

범위 밖: 단어 하나만 찾는 기능, 전체화면 독점 모드 캡처 우회, 혼합 DPI 실기 검증(모니터 1대).

## 3. 설계

### F1·F2 게임 창 따라가기 · 게임별 영역

```
영역 확정 → GameWindow::at(영역 중심, 이 앱 제외) → 게임 창 있음?
   ├ 예: key(실행 파일 경로), 영역(물리 픽셀, 창 클라이언트 기준), 그때의 클라이언트 크기 저장
   │     → settings: games/<key>/region, games/<key>/client, capture/game = key
   └ 아니오(바탕화면 등): 지금처럼 모니터 좌표만 저장

캡처 직전(자동 번역 틱, Ctrl+Alt+T, 미리보기) → followGame()
   ├ 앞에 있는 창이 저장된 다른 게임이면 그 게임으로 전환 (F2)
   ├ GameWindow::find(key, 최근 창 핸들)
   │    ├ 없음/최소화 → 이번 틱 건너뜀, 상태: "게임 창을 기다리는 중"
   │    └ 있음 → place(영역, 저장 크기, 현재 클라이언트) → toScreen() → 모니터·논리 좌표 영역
   └ 영역이 바뀌었으면 변화 감지 초기화, 영역 표시 갱신
```

- 기존 `GameWindow` 함수(`at`, `find`, `place`, `toScreen`, `relativeTo`, `toPhysical`)를 그대로 쓴다. 새로 추가하는 것은 앞 창을 읽는 `GameWindow::foreground()` 하나뿐이다.
- 설정 키에 경로를 그대로 쓰면 `/`가 그룹으로 해석되므로 Base64URL로 바꿔 저장한다.
- 이전 버전 설정(`capture/region`만 있음)은 지금처럼 동작한다(하위 호환).
- 모니터 해상도·배율이 바뀌어도 게임 창 기준이면 다시 계산되므로 자동 번역을 멈추지 않는다. 게임 기준이 아닐 때만 기존처럼 멈춘다.

### F3·F4 영역 지정

- 단축키 5번: Ctrl+Alt+R, 실패하면 Ctrl+Alt+F7. 메인 창이 최소화돼 있어도 동작하고, **마우스가 있는 모니터**에서 연다(게임이 있는 모니터).
- `RegionSelector`에 현재 영역을 넘겨 점선으로 보여 준다. 드래그하지 않고 Enter를 누르면 (방향키로 옮긴) 현재 영역을 확정한다. 드래그하고 놓으면 지금처럼 바로 확정한다(기존 흐름 유지).

### F5 읽은 범위 표시

- 클릭이 통과하는(`WS_EX_TRANSPARENT`) 테두리 창 `CaptureFlash`. 캡처가 **끝난 뒤** 0.6초 표시하므로 그 캡처에는 들어가지 않는다. 다음 캡처 전 숨김 목록에도 넣는다.

### 개발 중 발견한 것

- 테스트에서는 "게임" 역할의 창과 앱이 같은 실행 파일이라, 게임을 찾을 때 앱의 메인 창도 같은 프로그램으로 보였다. 실제 사용에서는 게임이 다른 실행 파일이다. 영역을 고를 때(`GameWindow::at`)는 이 앱의 창을 제외하므로 앱 창이 게임으로 등록되지 않는다. 테스트에서는 메인 창을 숨겨 겹침을 없앴다.
- 백그라운드 프로세스는 Windows가 앞 창으로 올려 주지 않는다. 그래서 앞 창 판단 함수를 주입할 수 있게 했다(`foregroundWindow_`). 실제 앞 창 조회 함수(`GameWindow::foreground`)는 기존 창 판별 함수(`visibleTarget`, `shell`)를 그대로 쓴다.
- Windows 헤더가 `near`를 매크로로 정의해 같은 이름의 테스트 함수가 컴파일되지 않았다(`closeTo`로 변경).

### 아직 확인하지 못한 것

- 실제 게임(전체화면·DirectX 창)에서 창 추적: 이 PC에 게임 화면 자료가 없음.
- 모니터 2대·혼합 배율에서 게임 창이 모니터를 넘어갈 때: 모니터 1대.
- F6(올려두기 이동 직후 재요청 지연, R-02) 측정.
