# 여러 영역 동시 번역과 화면 다듬기 — 계획과 결과

작성 2026-11-02 · 백로그 P-37 · 기준 커밋 `9d7cc41`

요청: "여러 영역 동시 번역 같은 편의 기능, 사용자 인터페이스 고도화 및 개발."

## 1. 문제

| 장면 | 지금 | 부족한 점 |
|---|---|---|
| 대사창 밖에 선택지가 뜸 (화면 가운데 "はい / いいえ") | 영역이 하나라 대사창만 읽음 | 선택지를 읽으려면 마우스 번역을 따로 해야 함 |
| 이름표·상태창이 대사창과 떨어져 있음 | 대사창 전체를 크게 잡으면 빈 화면까지 읽음 | 필요한 곳만 여러 개 고를 수 없음 |
| 자막 위치 | 원문 아래, 자리가 없으면 위 | 다른 영역을 덮으면 그 영역이 우리 자막을 다시 읽음 |
| 자막 숨기기 | 단축키·트레이에만 있음 | 메인 창에서 찾을 수 없음 |

[우선순위 목록](2026-11-02-priorities.ko.md)에서 "여러 영역"은 0.25점이었다. 사용자가 직접 요청해 효과·대상을 다시 매겼다. 효과 3, 대상 3(선택지는 비주얼 노벨에서 흔함), 확신 0.8, 노력 3으로 **2.4점**이 되어 개발한다.

## 2. 설계

- **추가 영역 최대 2개**(대사창 포함 3개).
  - 영역마다 변화 감지와 자막 창을 따로 둔다.
  - 읽기는 한 번에 하나다. 대사창이 먼저이고, 0.15초마다 추가 영역 중 바뀐 하나를 읽는다.
  - 대사창이 문장 끝을 기다리는 동안에는 추가 영역을 읽지 않는다. 대기 중인 줄을 버리지 않기 위해서다.
- **게임 창을 따라감**: 대사창이 게임 창 기준이면, 같은 게임 창 안의 추가 영역도 그 창 기준 좌표로 저장해 함께 움직인다. 다른 게임이 앞에 오면 그 게임의 추가 영역만 읽는다.
- **자막이 다른 영역을 덮지 않음**: `SubtitleOverlay::placement`에 피할 사각형 목록을 넘긴다. 아래 → 위 순으로 놓을 자리를 찾고, 없으면 자막을 띄우지 않는다. 메인 창 무대와 대사 기록에는 남는다. 자막이 다른 영역에 들어가면 그 영역이 우리 자막을 읽어 번역하는 되먹임이 생기기 때문이다.
- **추가 영역의 차이**:
  - 끝나지 않은 문장 대기를 하지 않는다. 선택지·이름표는 문장 끝 기호가 없는 경우가 많다.
  - 실패 시 재시도와 결과 창 대체도 하지 않는다.
- **화면**:
  - 더 보기(⋯) 메뉴: 자막 숨기기(체크), 영역 추가(선택지·이름표), 영역 모두 보기(1.5초 테두리), 추가 영역 지우기.
  - 트레이 메뉴: 영역 추가.
  - 메인 창: "추가 영역 n개도 함께 읽어요" 한 줄.
  - 설정 > 캡처: 추가 영역 줄(개수, 모두 지우기).
- **저장**: `capture/extraAreas` 배열(게임, 화면, 영역, 게임 창 기준 좌표). 자막 크기·배경 설정은 추가 영역 자막에도 적용된다.

## 3. 결과

| 확인 | 결과 |
|---|---|
| 자막 배치 | `captionPlacementAvoidsOtherRegions` 통과. 아래에 선택지가 있으면 위로 가고, 위아래가 모두 막히면 띄우지 않는다 |
| 두 영역 동시 자동 번역 | `extraRegionIsReadWithTheMainOne` 통과. 실제 화면에 대사창과 선택지 창을 띄우고 자동 번역을 켰다. 두 영역 모두 읽고 번역해 요청 2번, 대사 기록 2줄이 생겼다. 두 자막 모두 다른 영역을 덮지 않았다. 1초 더 기다려도 다시 읽지 않았고, 자동 번역을 끄면 추가 영역 자막도 사라졌다 |

- **실제 게임에서의 위치**: 선택지가 대사창을 덮는 게임에서 추가 영역이 대사창을 가려 두 영역이 서로를 바꾸는 경우 → P-13.
