# Codex 작업 지시서 — subtitle-translator 미디어 번역 모드 확장 (상용 수준 편의성·성능)

> 이 문서 전체를 Codex에 그대로 붙여 넣는다. 근거 설계: `docs/media-translation-plan.ko.md`. 이 지시서와 설계 문서가 다르면 **이 지시서가 우선**한다.

---

## 0. 역할과 목표

너는 Windows 데스크톱 앱(Qt 6.8.3 · C++17 · MSVC 2022 · CMake)을 상용 제품 수준으로 다듬는 시니어 엔지니어다.
저장소 `subtitle-translator`는 지금 "게임 대사창 OCR → DeepL 번역 → 화면 자막" 앱이다. 이를 **게임·뉴스·영화·커뮤니티 글 전반을 번역하는 미디어 번역 앱**으로 확장한다.

목표는 기능 개수가 아니라 다음 두 가지다.

1. **편의성**: 처음 쓰는 사람이 설명서 없이 2분 안에 첫 번역을 본다. 자주 쓰는 동작은 단축키 하나, 실수는 되돌릴 수 있고, 오류 문구는 "무엇이 / 왜 / 어떻게"를 한국어로 말한다.
2. **성능**: 아래 4절의 성능 예산을 **측정으로** 지킨다. 측정하지 않은 수치는 달성했다고 쓰지 않는다.

작업은 5절의 단계(0→4) 순서로 한다. **한 단계를 끝내고 완료 기준을 통과한 뒤에만** 다음 단계로 간다.

## 1. 저장소와 환경 (사실)

- 앱 소스 `src/`, 플랫폼 공통 C++ 코어 `core/` (Android와 공유, Qt 의존 금지), 테스트 `tests/`, 스크립트 `scripts/`, 문서 `docs/`
- `src/main_window.cpp` 약 64KB, 모든 화면 로직이 `MainWindow` 한 클래스에 있음
- 번역: `src/translation_service.*` — DeepL, 한 요청 최대 50조각(`MaxTexts`), `QNetworkAccessManager` 주입 가능(테스트용), 401/403/429/456이면 `requiresUserAction()`
- 테스트용 로컬 HTTP 서버: `tests/local_http_fixture.h`. **번역 테스트는 반드시 이것을 쓴다**
- 공통 코어: `core/src/core.cpp`의 `st_session` (원문 32KB 제한), `core/src/text.cpp` (이미 번역 언어인 부분은 보내지 않음)
- OCR: PaddleOCR PP-OCRv5(ONNX Runtime) 기본, Tesseract 대체. `src/ocr_service.*`, `src/paddle_ocr.*`
- 바뀜 감지: `src/change_detector.*` (0.4초 감시, 2회 안정, 3초 강제 읽기)
- 빌드: `scripts/build-windows.ps1` (도구 위치 `-ToolchainRoot`, 이 PC는 `D:\SubtitleTranslatorToolchain`), CTest 7개 그룹: translation_protocol, local_checks, paddle_ocr, change_detection, game_windows, windows_flow, shared_core
- 설정: 레지스트리 `HKCU\Software\PersonalTools\SubtitleTranslator`. API 키: Windows 자격 증명 `PersonalTools/SubtitleTranslator/DeepL`
- 최근 QA 결과: `tests/qa-2026-09-30/REPORT.md`, 이후 수정: `docs/qa-hardening-completion-2026-10-01.ko.md`
- QA 자동화 도구: `tests/qa-2026-09-30/suite/` (가짜 게임 창 `fake-game.ps1`, 앱 시나리오 `suite-app.ps1`). 재사용·확장해도 된다

시작하기 전에 위 사실을 실제 파일로 확인하고, 다른 점이 있으면 작업 보고서 첫머리에 적는다.

## 2. 절대 규칙

### 2-1. 비밀 정보·비용

- DeepL API 키를 출력·로그·파일·커밋·테스트 픽스처에 남기지 않는다. 키 형식 문자열 검색 결과는 **개수만** 보고한다
- **자동 테스트는 실제 DeepL을 부르지 않는다.** 전송 계층 주입 + `local_http_fixture.h`로 대체한다
- 실제 DeepL 호출이 꼭 필요하면 작업을 멈추고 사람에게 묻는다. 허락받은 경우에도 호출마다 시각·글자 수를 `docs/impl/deepl-calls.csv`에 기록하고, 한 단계당 20회·2,000자를 넘기지 않는다
- 설정 창 "키 저장"을 끈 채 저장하면 자격 증명의 키가 지워진다. 테스트·스크립트가 사용자의 실제 설정이나 자격 증명을 바꾸지 않도록 **별도 설정 경로**(조직 이름이나 애플리케이션 이름을 테스트용으로 바꾼 `QSettings`)를 쓴다

### 2-2. 법·정책

- DRM 보호 영상(넷플릭스 등)의 화면·소리 캡처를 우회하는 코드를 만들지 않는다. 검은 화면·무음을 감지하면 안내만 한다
- 웹 페이지를 앱이 직접 내려받아 긁어 오는 기능을 만들지 않는다. 글은 사용자가 복사하거나 화면에 띄운 것만 다룬다
- 새 의존성은 라이선스를 확인하고 `docs/THIRD_PARTY_NOTICES.md`에 추가한다. whisper.cpp(MIT)는 허용. ffmpeg는 LGPL 빌드를 **동적 링크**로만, GPL 구성 금지

### 2-3. 코드·저장소

- 작업 브랜치 `feature/media-modes`에서 작업한다. `main`에 직접 커밋하지 않는다. 강제 푸시·히스토리 재작성 금지
- 커밋은 "한 가지 변경 + 그 테스트" 단위로 작게. 메시지는 `<영역>: <변경>` (예: `capture: exclude overlay windows from capture`)
- 기존 동작(게임 모드)을 깨지 않는다. 매 커밋 전 CTest 7개 그룹 전부 통과
- `core/`에는 Qt·Windows 헤더를 넣지 않는다 (Android 공유)
- 컴파일 경고 0개 유지(MSVC `/W4` 수준에서 새 경고를 만들지 않는다)
- 바꾸는 사용자 문구는 모두 한국어. 문체는 지금 앱과 같게 (짧은 평서문, "~합니다")

### 2-4. 정직한 보고

- 실행하지 못한 검증은 "미검증"으로 쓴다. 예: Windows GUI를 띄울 수 없는 환경이면 GUI 시나리오는 미검증
- 성능 수치는 측정 방법·횟수·기계 사양과 함께 쓴다. 한 번 잰 값을 대표값으로 쓰지 않는다 (최소 20회, 중앙값·p95)

## 3. 편의성 기준 (상용 수준 체크리스트)

각 단계가 끝날 때 해당 항목을 점검하고 보고서에 표로 남긴다.

**처음 사용**
- [ ] 첫 실행 마법사: 용도 선택(게임 / 영상 / 글 / 자막 파일 / 음성) → 필요한 것만 묻기 → 바로 시험 번역. 키가 없어도 OCR·받아쓰기까지는 체험 가능
- [ ] 각 모드 첫 진입 시 3줄 이내 안내 + "다시 보지 않기"

**매일 사용**
- [ ] 모드 전환: 메인 창 상단 탭 + 단축키 `Ctrl+Alt+1`(게임) `2`(영상) `3`(글) `4`(음성). 등록 실패 시 버튼으로 대체하고 상태 줄에 이유 표시
- [ ] 모든 단축키를 설정에서 바꿀 수 있음. 충돌 감지 시 즉시 알림
- [ ] 시스템 트레이 아이콘: 현재 모드·켜짐/꺼짐 표시, 우클릭 메뉴로 모드 전환·일시정지·종료
- [ ] 모드별 마지막 설정(영역·언어·배치)을 기억
- [ ] 화면 자막: 글자 크기·배경 불투명도·위치(원문 아래 / 위 / 덮기) 설정, 실시간 미리보기
- [ ] 최근 번역 기록 창: 검색, 복사, 원문/번역 나란히, TXT·SRT 내보내기. 기본은 "앱 종료 시 삭제", 설정에서 보관 선택
- [ ] 사용량 표시: 이번 세션·이번 달 DeepL 글자 수, 남은 양(`/v2/usage`), 사용자 상한 도달 시 자동 정지와 안내

**문제 상황**
- [ ] 오류 문구는 "무엇이 / 왜 / 어떻게" 세 부분. 예: "번역을 멈췄습니다 · DeepL 월 한도를 넘었습니다 · 설정 → 사용량에서 확인하세요"
- [ ] 보호된 영상(검은 화면·무음) 감지 시 한 번만 안내
- [ ] 같은 앱을 두 번 실행하면 두 번째 실행은 첫 번째 창을 앞으로 가져오고 종료 (단일 인스턴스). QA에서 중복 프로세스가 단축키를 잡아 기능이 멈춘 사례가 있었다
- [ ] 진단 로그: `%LOCALAPPDATA%\SubtitleTranslator\logs`에 회전 로그(최대 5MB × 3). 단계별 지연(캡처·OCR·번역·표시), 오류 코드. **원문·번역문·키는 기본적으로 기록하지 않음**(설정에서 켤 때만)
- [ ] 설정 내보내기·가져오기(키 제외)

**접근성·환경**
- [ ] 125%·150% 배율, 모니터 2대(배율이 다른 경우 포함)에서 영역 선택·자막 위치가 맞음
- [ ] 키보드만으로 모든 설정 조작 가능, 탭 순서 자연스러움
- [ ] 다크/라이트 테마는 Windows 설정을 따름

## 4. 성능 예산 (측정해서 지킨다)

측정 도구를 먼저 만든다: 앱 내부 단계별 타이머(4-1의 로그) + 외부 측정 스크립트(가짜 창 이벤트 시각과 화면 자막 표시 시각 비교, 기존 `suite-app.ps1` 방식 재사용). 결과는 `docs/impl/perf-<단계>.md`에 남긴다.

| 항목 | 예산 | 비고 |
|---|---|---|
| UI 스레드 정지 | 한 번에 50ms 초과 0회 | 캡처·이미지 비교를 작업 스레드로 옮긴다 (지금은 GUI 스레드, QA 위험 R-15) |
| 대기 상태 CPU (자동 켬, 화면 변화 없음) | 한 코어의 1% 이하 | 지금 측정: 24코어 PC에서 전체의 0.01% |
| 앱 시작 → 메인 창 | 중앙값 300ms 이하 | 지금 측정 160ms. 모델은 지연 적재 |
| 메모리, 게임/영상 모드 1시간 | 워밍업 후 증가 20MB 이하, 핸들 증가 50 이하 | 지금 PaddleOCR 적재 후 약 273MB |
| 영상 자막: 자막 바뀜 → OCR 원문 | 중앙값 600ms, p95 900ms | 자막 띠 영역 820×140 기준 |
| 영상 자막: 자막 바뀜 → 번역 자막 표시 | 중앙값 2.0s, p95 3.0s | DeepL 포함. 로컬 서버 기준은 중앙값 800ms 이하 |
| 같은 원문 재표시 (캐시) | 100ms 이하, DeepL 호출 0 | |
| 자막 파일: 2시간 영화(.srt 1,500줄) | 로컬 서버 기준 30초 이하, 진행률 표시, 취소 즉시 | 실제 DeepL은 네트워크 의존이라 참고값 |
| 글 모드: 3천 단어 | 로컬 서버 기준 5초 이하, 문단 순서 100% 유지 | |
| 음성: 말 끝 → 번역 자막 | GPU 있을 때 중앙값 3s, CPU(small 모델) 중앙값 5s | 실측 후 모델 기본값 결정 |
| 음성 모드 CPU | 말 없을 때 한 코어의 3% 이하 | VAD로 무음 구간 인식 생략 |

예산을 못 지키면 원인과 측정값을 보고하고, 예산을 낮추지 말고 사람에게 묻는다.

## 5. 단계별 작업

### 단계 0 — 기반 정리 (다른 단계보다 먼저)

1. **`MainWindow` 분리** (동작 변경 없이)
   - `ModeProfile`(모드별 설정 묶음), `ScreenTextSource`(캡처+바뀜 감지+OCR), `TranslationQueue`(조각 나누기·50개 단위 요청·캐시·사용량 집계), `SubtitlePresenter`(화면 자막), `HistoryStore`(기록)로 나눈다
   - 모드 = 입력(Source) + 표시(Presenter) + 설정(Profile) 조합. 한 번에 한 모드만 실행, 전환 시 이전 작업 취소
   - 분리 전후로 CTest 7/7 + `tests/qa-2026-09-30/run-selfcheck2.cmd` 결과가 같아야 한다
2. **캡처를 작업 스레드로**: 0.4초 캡처·축소·비교를 GUI 스레드 밖으로. UI 정지 측정 추가
3. **자기 창 캡처 제외**: 화면 자막·결과·기록 창에 `SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)` (Windows 10 2004+). 지금 캡처 경로(Qt `QScreen::grabWindow`)에서 실제로 빠지는지 **테스트로 확인**한다. 빠지지 않으면 Windows Graphics Capture 또는 DXGI Desktop Duplication 경로를 비교해 제안하고 멈춘다. 구버전 Windows는 지금 방식(겹치면 자동 번역 중지) 유지
4. **단일 인스턴스**: `QLocalServer` 기반. 두 번째 실행은 인수(`--auto` 등)를 첫 번째로 넘기고 종료
5. **진단 로그·단계별 타이머** (3절)
6. **남은 QA 결함** (`docs/qa-hardening-completion-2026-10-01.ko.md` "남은 제한")
   - 기호만 있는 줄이 번역 대상이 되는 문제 (B-04): 글자 비율 기준으로 번역 제외, `Lv.10` 같은 숫자·점 토큰 보존
   - 단독 `|`가 `I`가 되는 후처리 (R-19, `src/ocr_service.cpp` cleanText): 앞뒤가 영문 단어일 때만 바꾼다
   - 잡음 배경 오인식: 신뢰도·글자 수 하한
   - R-02: 취소 후 PaddleOCR 추론 계속 → 협조적 취소 플래그
   - 각 수정은 재현 테스트를 먼저 추가(실패 확인) → 수정 → 통과
7. **번역 엔진 인터페이스**: `TranslationService`를 `ITranslator` 뒤로. 구현은 DeepL만. 이후 다른 엔진을 붙일 수 있게 구조만

**완료 기준**: CTest 전부 통과 + 새 테스트, UI 정지 50ms 초과 0회(게임 모드 10분), 캡처 제외 동작 확인 결과, QA 셀프체크 동일, 경고 0

### 단계 1 — 영상 자막 모드

- 프리셋 "영상 하단 자막": 선택한 창(또는 화면)의 아래 20%를 기본 영역으로 제안, 사용자가 조정
- 바뀜 감지 프로필: 0.2–0.25초 감시, 1회 안정, 자막 띠 안의 **글자 영역 변화**로 판정(움직이는 배경 무시)
- 유튜브 자동 생성 자막(단어가 하나씩 붙는 방식)은 지금의 "완성될 때까지 기다림" 규칙 유지
- 화면 자막 배치에 "원문 위 덮기"(반투명 배경, 원문 자막 크기에 맞춤) 추가
- 다음 자막이 뜰 때까지 이전 번역 유지. 번역이 늦게 와도 그 자막이 아직 화면에 있으면 표시
- 기록 창 + 시각 기반 간이 SRT 내보내기
- 보호된 영상 감지: 영역이 연속 N초 거의 검은색이면 1회 안내
- 테스트: `fake-game.ps1`을 넓혀 **가짜 영상 플레이어**(움직이는 배경 + 1–4초 자막 + 반투명 띠 + 단어 단위 자막) 시나리오 작성. 로컬 번역 서버로 자동 측정

**완료 기준**: 가짜 플레이어 자막 200개 중 누락 5% 이하, 4절 영상 예산 충족, 빈 자막 구간 가짜 글자 0회, 게임 모드 회귀 없음

### 단계 2 — 자막 파일 모드

- `.srt`, `.vtt`, `.ass` 읽기·쓰기를 **`core/`에** (UTF-8/UTF-16 BOM, CRLF/LF, `.ass` 스타일 태그 보존)
- 여러 줄로 나뉜 한 문장은 묶어서 번역하고 원래 줄 구조로 되돌림
- 번역 전 예상 글자 수·요청 수 표시 → 확인 후 진행. 진행률·취소·이어하기(줄 단위 캐시)
- 출력: `원본이름.<언어>.srt`, 원본 덮어쓰기 금지. 선택: 원문+번역 두 줄
- 영상 파일을 드롭하면 같은 이름 자막을 자동 탐지 (내장 자막 추출은 이 단계 범위 밖)
- 테스트: 코어 단위 테스트(경계: 빈 줄, 겹치는 시간, 1만 줄, 깨진 파일), 로컬 서버로 1,500줄 처리 시간

**완료 기준**: 타이밍 100% 보존, 태그 보존, 1,500줄 30초 이하(로컬 서버), 깨진 파일에서 앱이 죽지 않고 줄 번호로 안내

### 단계 3 — 글 모드

- 입력: 클립보드(`Ctrl+Alt+3` 누르면 현재 클립보드 글 번역), 화면 영역 OCR(문단 순서 유지)
- 문단 단위로 나눠 50조각·32KB 제한을 넘지 않게 여러 요청으로 보내고 순서대로 합침
- 결과 창: 원문/번역 나란히, 문단 클릭 시 반대쪽 강조, 전체 복사
- 커뮤니티 글 프리셋: URL·@멘션·#해시태그·이모지·코드 블록은 번역에서 보호
- 용어집 1차: 앱 내부 치환표(CSV 가져오기·내보내기, 모드별). 번역 전 보호 → 번역 후 복원

**완료 기준**: 3천 단어 5초 이하(로컬 서버), 문단 순서 100%, 보호 토큰 원형 유지 100%, 용어집 적용 테스트

### 단계 4 — 음성 모드

- 소리 받기: WASAPI 루프백(공유 모드), 16kHz 모노 변환. 장치 변경(헤드셋 연결 등) 자동 재연결
- 말 구간 감지(VAD) → whisper.cpp 받아쓰기 → 문장 단위로 묶어 번역 → 화면 자막·기록
- 모델은 설치본에 넣지 않음. 처음 켤 때 크기·용도 안내 후 내려받기, SHA-256 확인(`scripts/prepare-paddle-models.ps1` 방식). 후보: `small-q5_1`(181MiB, CPU 기본), `large-v3-turbo-q5_0`(547MiB, GPU)
- GPU(CUDA/Vulkan) 감지 시 자동 선택, 없으면 CPU. 실측 후 기본값 결정
- DRM 오디오는 무음으로 들어옴 → 무음 지속 시 1회 안내
- 첫 실행 시 "PC 소리가 받아쓰기되고, 번역 시 글자가 DeepL로 전송됩니다" 동의
- 사용량 상한 기본값 켬(세션 5만 자)
- 테스트: 저작권 문제 없는 샘플 음성(직접 생성한 TTS 등)을 가상 재생해 지연·단어 오류율 측정

**완료 기준**: 4절 음성 예산, 무음 시 CPU 예산, 장치 변경 후 10초 안에 복구, 1시간 메모리 예산

### 단계 5 — 선택 (사람이 요청할 때만)

영상 파일 소리 → SRT 생성, mkv 내장 자막 추출(ffmpeg LGPL 동적), DeepL 용어집 API, 스크롤 연속 읽기

## 7. 작업 방식과 보고

각 단계마다 다음 순서로 진행한다.

1. **계획**: 바꿀 파일, 새 클래스, 테스트 목록, 위험을 `docs/impl/<단계>-plan.md`에 쓴다. 기존 동작에 영향이 큰 결정(캡처 방식 교체, 새 의존성)은 여기서 멈추고 사람의 확인을 받는다
2. **구현**: 테스트 먼저(실패 확인) → 구현 → 통과. 작은 커밋
3. **검증**: CTest 전부, 새 테스트, 성능 측정, 3절 체크리스트, QA 셀프체크
4. **보고**: `docs/impl/<단계>-report.md`

보고서 형식 (한국어):

```text
## 간단한 사전 설명
(무엇을 했고 완료 기준을 통과했는지 3–5줄)

## 자세한 설명
- 변경 요약 (파일·클래스)
- 테스트 결과 (그룹별 통과 수, 새 테스트)
- 성능 (항목 / 예산 / 측정값 중앙값·p95 / 횟수 / 판정)
- 편의성 체크리스트 (항목 / 충족 / 근거)
- 미검증 항목과 이유
- 알려진 문제·다음 단계 제안
- DeepL 실제 호출: N회 / M자 (없으면 0)
- 키 형식 문자열 검색: N건
```

막히면 추측으로 진행하지 말고, 시도한 것·관찰한 것·선택지를 적어 사람에게 묻는다.
