# 미디어 번역 모드 — 지시서 검토와 설계 (단계 0~3)

- 작성: 2026-10-01, 대상 브랜치 `feature/media-modes`
- 입력: `docs/codex-prompt-media-modes.ko.md`(지시서), `docs/media-translation-plan.ko.md`(설계 초안), 기준 코드 `9d13db9`
- 범위: 사용자가 정한 대로 **단계 0~3**(기반·영상 자막·자막 파일·글). 음성(단계 4)은 새 의존성(whisper.cpp)이 필요해 이번 범위에서 뺐다.

## 간단한 사전 설명

지시서의 방향(모드 = 입력 + 표시 + 설정, 측정으로 성능 확인, 비용·개인정보 보호)은 맞다. 다만 그대로 구현하면 사용자가 불편해지거나 기능이 틀리게 동작하는 곳이 **12군데** 있어 설계에서 고쳤다. 가장 중요한 세 가지는 다음과 같다.

1. **캡처 제외는 양날의 칼이다.** 번역 자막을 캡처에서 빼면 스크린샷·방송(OBS·디스코드)에도 안 보인다. 그래서 설정으로 두고(기본 켬) 이유를 화면에 적는다.
2. **영상 자막은 게임처럼 한 줄씩 차례로 처리하면 놓친다.** 1~4초짜리 자막은 번역(약 1.2초)을 기다리는 동안 지나간다. 읽기와 번역을 겹쳐 돌리고, 가장 최근 자막을 먼저 처리한다.
3. **한국에서 흔한 CP949·Shift-JIS 자막 파일**을 지시서는 다루지 않는다. 읽지 못하면 자막 파일 모드가 쓸모없어지므로 인코딩 추정과 직접 선택을 넣는다.

기존 게임 모드는 화면 테스트 34개가 세부 동작을 고정하고 있다. 그래서 `MainWindow`를 한 번에 갈아엎지 않고, 공통 부품을 하나씩 떼어 내 게임 모드와 새 모드가 같이 쓰게 한다.

## 자세한 설명

### 1. 지시서 검토 — 고친 점 12가지

| # | 지시서 내용 | 문제 | 설계에서 바꾼 점 |
|---|---|---|---|
| 1 | 자막·결과·기록 창에 `WDA_EXCLUDEFROMCAPTURE` | 번역 자막이 스크린샷·녹화·방송에서도 사라진다. 번역을 캡처해 공유하려는 사용자에게는 고장처럼 보인다 | 설정 "번역 창을 화면 캡처에서 숨기기"(기본 켬)와 이유를 적은 안내. 메인 창은 제외하지 않음(사용자가 앱 화면을 캡처해 문의할 수 있게) |
| 2 | 영상 모드 "원문 위 덮기" | 캡처 제외가 없으면 덮은 자막을 다시 읽는다(되먹임) | 제외가 켜져 있고 OS가 지원할 때만 덮기 선택 가능. 아니면 아래/위 배치로 자동 전환하고 이유 표시 |
| 3 | `Ctrl+Alt+1~4` 모드 전환 | 유럽식 자판에서 `Ctrl+Alt`는 AltGr이라 `@`, `²` 같은 글자 입력을 가로챈다. 한국어 자판은 문제없음 | 모든 단축키를 설정에서 바꿀 수 있게 하고, 등록 실패·중복을 바로 알림. `Ctrl+Alt+4`(음성)는 단계 4 전에는 등록하지 않음 |
| 4 | 보호된 영상: 자막 영역이 N초 검으면 안내 | 영화의 자막은 대개 검은 레터박스 띠 위에 나온다. 자막 없는 구간마다 "보호된 영상" 오탐 | 자막 띠가 아니라 **선택한 창 전체**가 6초 이상 완전한 검정(0,0,0)일 때만 1회 안내. DRM 화면은 순수 검정이고, 실제 어두운 장면은 순수 검정이 드묾 |
| 5 | 다음 자막까지 이전 번역 유지 | 영상이 끝나거나 자막 없는 장면에서 지난 번역이 계속 떠 있다 | 다음 자막까지 유지하되, 원문 자막이 사라진 뒤 5초가 지나면 숨김(설정 가능) |
| 6 | 감지 0.2~0.25초·1회 안정 + 유튜브 자동 자막은 "완성될 때까지 기다림" | 둘이 충돌한다. 1회 안정이면 단어가 붙을 때마다 읽고 번역해 DeepL 사용량이 몇 배가 된다 | **새 자막(글자 교체)은 빨리, 단어 추가(글자 성장)는 완성될 때까지** 구분하는 판정 추가 |
| 7 | 게임 모드처럼 처리 중이면 다음 화면을 건너뜀 | 번역을 기다리는 1.2초 동안 짧은 자막을 놓친다 | 영상 모드는 화면 감시를 작업 스레드에서 계속하고, OCR은 최신 자막 우선, 번역은 최대 2건 동시 |
| 8 | 캐시: `st_session`(마지막 한 줄) | 되감기·반복 대사에서 같은 문장을 다시 보낸다 | `TranslationQueue`에 최근 2,000문장 캐시(언어 쌍별) |
| 9 | 403/429/456이면 자동 번역 중지 (QA R-04) | 사용자가 직접 시작한 자막 파일 1,500줄 작업이 일시적 429 한 번에 멈춘다 | 자동 감시 모드는 지금처럼 중지. **사용자가 시작한 묶음 작업**은 429·5xx·시간 초과만 1·2·4초 간격 최대 3회 재시도, 401/403/456은 즉시 중지 |
| 10 | 자막 파일 UTF-8/UTF-16만 | 국내 자막 파일은 CP949(EUC-KR), 일본 자막은 Shift-JIS가 많다 | UTF 확인 → 실패하면 시스템 코드 페이지·CP949·Shift-JIS 순으로 추정, 화면에서 직접 바꿀 수 있게. 저장은 UTF-8(BOM) |
| 11 | 여러 줄 한 문장을 묶어 번역 | 구간(큐) 사이에 걸친 문장을 합치면 다시 나눌 때 어순이 다른 언어(영→한)에서 어색할 수 있다 | 큐 안의 줄은 항상 묶음. 큐 사이 이어 붙이기는 옵션(기본 켬, 최대 3큐), 원문 글자 비율로 나눔. 대신 앞뒤 큐를 DeepL `context`로 보내 품질 보완 |
| 12 | `.ass` 태그·커뮤니티 글 보호 토큰 | 자리표시자(예: `⟦0⟧`)는 번역기가 옮기거나 지우는 일이 잦다 | DeepL 공식 기능 `tag_handling=xml` + `ignore_tags`로 보호. 앞뒤 태그는 아예 보내지 않음. 사라진 태그는 끝에 복원하고 개수를 보고 |

그 밖에 지켜야 할 제약:

- **단일 인스턴스는 `main()`에 둔다.** 테스트가 한 프로세스에서 `MainWindow`를 여러 번 만든다.
- **트레이 아이콘·첫 실행 마법사는 테스트 모드에서 만들지 않는다.**
- **다크 모드**: 지금 상태 표시줄 등은 밝은 색이 고정(`#edf4fa`)이라 Windows 다크 모드에서 글자가 안 보인다. 팔레트 색으로 바꾼다.
- **로그**: 원문·번역문·키·파일 경로를 기본으로 남기지 않는다. 시간·단계·오류 코드만.

### 2. 구조

```text
main.cpp ─ SingleInstance(두 번째 실행 → 첫 창 앞으로, 인수 전달) ─ Diagnostics(회전 로그)
  └─ MainWindow : 셸 (모드 탭, 언어 줄, 상태 줄, 트레이, 단축키 배선, 설정)
       ├─ 게임 페이지 ── 기존 흐름 (st_session 상태 머신 유지)
       ├─ 영상 페이지 ── VideoMode ─┐
       ├─ 글 페이지 ──── TextMode ──┤
       └─ 자막 파일 ──── SubtitleFileJob
  공통 부품 (모두 MainWindow 밖, 단독 테스트 가능)
       HotkeyManager       단축키 등록·변경·충돌 확인
       CaptureWorker       작업 스레드: GDI 캡처 + 바뀜 감지(모드별 프로필)
       OcrService          (기존) 모드끼리 공유 — PaddleOCR 모델을 한 번만 적재
       TranslationQueue    ITranslator(DeepL) 위: 캐시·50조각/30KB 나누기·재시도·동시 2건·취소
       UsageMeter          세션·월 글자 수, 상한
       SubtitlePresenter   화면 자막 (아래/위/덮기, 크기, 배경, 캡처 제외)
       HistoryStore        기록 (메모리, 선택 시 보관) + HistoryWindow (검색·복사·TXT/SRT)
       ModeProfile         모드별 설정 (게임은 기존 키 그대로)
  core/ (Qt·Windows 없음, Android 공유)
       text        기존 + 기호만 있는 조각 판정, 숫자 토큰 보존
       subtitle_file  SRT/VTT/ASS 읽기·쓰기 (타이밍은 원본 바이트 그대로)
       document    문단 나누기, 보호 토큰·용어집 → XML, 요청 계획(50조각·바이트)
```

**게임 모드를 지금 바꾸지 않는 부분**: 요청 상태 머신(`st_session`, `busy_`, `request_`)은 화면 테스트 34개가 세부 순서를 고정하고 있다. 이 부분을 옮기면 테스트 대부분을 다시 써야 해서 회귀를 확인할 기준이 사라진다. 그래서 단축키·화면 자막·캡처 스레드·사용량·기록만 공통 부품으로 연결하고, 상태 머신 이전은 다음 작업으로 남긴다.

### 3. 처리 흐름

**게임 모드 (바뀌는 점만)**

```text
GUI 0.4초 타이머: 모니터·창 겹침 확인(가벼움) → CaptureWorker에 "한 번 확인" 요청
CaptureWorker(작업 스레드): 캡처 → 축소·비교 → 처리할 때만 이미지 전달
GUI: processImage → (기존 그대로) OCR → 번역 → 자막 + [새로] 사용량·기록
```

**영상 모드**

```text
CaptureWorker 0.25초: 글자 윤곽 마스크로 비교 (움직이는 배경 무시)
   교체 → 1회 안정 후 즉시 / 성장(단어 추가) → 0.75초 멈출 때까지 / 빈 화면 → 자막 숨김 예약
OCR: 한 번에 하나, 대기 중이면 가장 최근 화면만 남김
번역: 캐시 확인 → 없으면 요청(동시 2건), 앞 자막 1줄을 context로
표시: 아직 화면에 있는 자막이면 표시, 지나갔으면 기록에만
```

### 4. 성능 측정 방법

| 측정 | 방법 |
|---|---|
| UI 정지 | `UiStallMonitor`: GUI 스레드에서 16ms 타이머의 실제 간격을 재서 50ms 넘게 늦으면 1회. `--perf` 또는 테스트에서만 켬(평소 CPU 사용 없음) |
| 단계별 지연 | 요청마다 캡처·OCR·번역·표시 시각을 로그 `st.perf`에 기록 |
| 영상 지연·누락 | Qt로 만든 **가짜 영상 플레이어**(움직이는 배경 + 1~4초 자막 + 반투명 띠 + 단어 추가 자막)가 자막을 띄운 정확한 시각과, 실제 파이프라인(실제 캡처·실제 PaddleOCR·로컬 번역 서버)이 읽고 표시한 시각을 비교 |
| 자막 파일·글 | 로컬 번역 서버로 1,500줄·3천 단어 처리 시간, 20회 중앙값·p95 |
| 대기 CPU·메모리 | 프로세스 CPU 시간·작업 집합·핸들 수를 일정 간격으로 기록 |

### 6. 위험

| 위험 | 대응 |
|---|---|
| 캡처를 작업 스레드로 옮기며 게임 모드 시점이 바뀜 | GUI 타이머 주기·처리 중 건너뛰기 규칙을 그대로 두고 무거운 부분만 옮김. `autoTranslateReadsEachNewLineOnce` 등 기존 테스트로 확인 |
| 화면 테스트가 사용자 화면에 창을 띄움 | 설치본 종료 확인 후 실행. 테스트 설정은 별도 조직 이름 |
| DeepL `context`·`tag_handling` 동작 | 공식 문서 기준 구현. 실제 DeepL 호출은 사용자 허락 없이는 하지 않으므로 **실서버 동작은 미검증**으로 보고 |
| 영상 판정이 실제 유튜브 화면과 다를 수 있음 | 가짜 플레이어는 대표 형태만 재현. 실제 영상 검증은 사용자 확인 항목으로 보고 |
