# 자동 번역 누락 수정 · Claude 작업 인계 확인 (2026-09-30)

## 간단한 사전 설명

사용자가 지적한 대상은 마우스 번역이 아니라 **자동 번역에서 특정 부분 또는 문장 끝을 놓치는 현상**입니다. Claude 로그를 먼저 확인하고 기존 글자 위치 탐지 개선은 유지했습니다. 이번에는 자동 캡처의 변화 감지와 OCR 실패 복구에서 재현한 문제를 수정했습니다.

## 자세한 설명

### 인계 시점 확인

- 기준 커밋: `d5f87e1`. Claude는 글자 위치 탐지 모델과 `GameWindow` 모듈·테스트를 추가했습니다.
- 마지막 대화는 2026-09-30 01:05 KST경 코드 리뷰 결과 확인 → 게임별 영역 연결 → 영어/일본어 실험 순서로 진행하겠다는 내용이며, 이후 사용량 제한으로 중단됐습니다.
- 두 workflow의 바깥 상태는 completed였지만 journal에는 failed가 기록돼 있었고, 준비 결과는 null, 리뷰 확정 수는 0이었습니다. 따라서 리뷰 통과나 영어/일본어 실험 완료로 취급하지 않았습니다.
- `GameWindow` 모듈은 빌드되고 별도 테스트는 있지만 `MainWindow`에 연결되지 않았습니다. 게임 이동을 자동으로 따라간다고 보고하지 않습니다.
- 설치 EXE와 dist EXE가 서로 달랐습니다. 이번에는 최종 빌드 후 설치·파일 해시 일치를 다시 확인합니다.
- 현재 OCR 설정은 `jpn+eng+kor` / Paddle였습니다. 과거 스크린샷의 영어 선택 상태를 현재 원인으로 단정하지 않았고 사용자 언어 설정은 바꾸지 않았습니다.
- 미완료 영어/일본어 실험 준비 파일 `scripts/make-enja-fixtures.py`와 도구 폴더 실험 자료는 수정하지 않았습니다.

### 재현 및 수정

| 조건 | 수정 전 | 수정 후 |
|---|---|---|
| 2200×420 영역의 18px 일본어 마침표 / 영어 느낌표 추가 | 비교 이미지를 160×48 안으로 줄여 둘 다 Unchanged, 다시 OCR하지 않음 | 최대 960×320 비교 이미지로 두 변화 모두 감지 |
| 배경이 400ms 폴링 두 번마다 바뀜 | 중간 한 번 조용할 때마다 타이머 초기화, 테스트 전체에서 OCR 0회 | 연속 2회 안정돼야 대기 종료; 불안정한 채 3초가 지나면 확인 |
| 움직이는 중 3초 제한으로 먼저 읽은 뒤 화면이 멈춤 | 먼저 읽은 상태를 최종 결과로 취급할 수 있음 | 안정된 화면을 한 번 더 확인, 이후 중복 억제 |
| OCR 실패 후 화면은 그대로 | 이미 처리한 이미지로 기억해 재시도하지 않음 | 3초 간격 최대 2회 OCR 재확인, 성공한 정지 화면은 추가 확인 중단 |

작은 픽셀 잡음 테스트는 유지했습니다. 비교 이미지가 커져 기존보다 작은 배경 변화도 감지할 수 있습니다. 변화 중에는 3초 대기 제한과 기존 원문 중복 처리로 불필요한 반복을 줄입니다. 이미지 비교 버퍼 3개 기준 최대 약 0.9MiB라는 계산상 상한이며, 전체 프로세스 메모리 실측값은 아닙니다. 새 OCR 모델이나 네트워크 서비스를 추가하지 않았습니다.

재시도는 OCR 실패/빈 원문에만 적용하며, 번역 API 실패를 자동으로 재전송하지 않습니다. OCR 복구 후 새 원문을 번역할 때는 기존 키·동의 설정을 따릅니다. 공통 C++ 코어는 변경하지 않았습니다.

### 실제 검증

- Windows Release 빌드 및 CTest **7개 그룹 통과**, 33.48초.
- 변화 감지: 수정 전 재현 3개 실패, 수정 후 14개 통과(초기화·정리 포함).
- Windows UI: 19개 통과(초기화·정리 포함). 실패 테스트에서는 테스트용 잘못된 모델 파일로 실제 ONNX 로딩 실패를 유발하고, 정상 모델 복원 후 **동일한 화면**을 재캡처하여 PaddleOCR이 일본어 `天気`를 실제로 읽는지 확인했습니다. 성공 후 불필요한 추가 요청이 없는지도 확인했습니다.
- 나머지: translation_protocol 13, local_checks 20, paddle_ocr 42, game_windows 7, shared_core 통과.
- 기존 마우스 테스트는 사용자의 포인터 이동과 큐에 넣은 이벤트가 경쟁하지 않도록 실제 커서를 옮긴 직후 nativeEvent를 동기 호출합니다. 물리 키보드 입력 검증으로 해석하지 않습니다.
- DeepL 외부 요청은 이번 검증에서 보내지 않았습니다. 번역 프로토콜 테스트는 준비된 JSON 응답과 요청 본문을 검사하는 단위 테스트입니다. 로컬 HTTP 서버와 실제 HTTP 시간 초과·취소·429 응답 경로는 검증하지 않았습니다.

### 남은 확인

- 사용자가 실패를 겪은 실제 게임 화면은 이번 턴에 확보하지 못했습니다. 위 수정이 그 화면의 모든 글자를 정확하게 인식한다는 뜻은 아닙니다.
- 자동 번역이 놓친 화면에서 Ctrl+Alt+T를 눌러도 원문이 일부만 나오면, 변화 감지와 별도로 캡처 범위 또는 글자 탐지·인식의 문제를 확인해야 합니다.
- 게임 창 이동 추적/게임별 저장 영역 연결, 미완료 영어·일본어 실험, 실제 게임별 OCR 정확도는 별도 미완료 항목입니다.
- 캡처 바깥의 글자는 읽을 수 없으므로 원문 문장 전체가 영역에 포함돼야 합니다. 이동한 게임 창은 영역을 다시 선택해야 합니다.
