# Windows QA 결함 수정 — 2026-10-01

## 범위와 기준

사용자가 전달한 Cowork Windows 실행 검증(기준 HEAD `0b8ed75`)을 바탕으로 D-01(단색 이미지 오인식), R01(결과 창이 캡처 영역을 가려 자동 번역 대기), I02(검증 설명 오류)를 우선 처리했다. 원본 `tests/qa-2026-09-30/` 자료는 수정하지 않았다. Windows 전용 서비스/UI만 변경했으며 모바일 공통 C++ 코어는 변경하지 않았다.

## 재현과 수정

### D-01: 단색 이미지 오인식

수정 전 실행에서 흰색 200×60은 `Se`, 검정 200×60은 `a`, 흰색 1200×300은 PaddleOCR 경로에서 `[`로 재현됐다. UI 이미지 처리 경로에서도 빈 화면이 비어 있지 않은 원문으로 들어오는 것을 재현했다.

원본 해상도의 모든 픽셀이 같은지 OCR 전에 비동기로 검사한다. 완전한 단색이면 엔진을 실행하지 않고 빈 OCR 결과를 공통 코어의 ST_EMPTY 경로로 전달한다. CLI는 기존 계약에 따라 종료 코드 3, 자동 번역 UI는 이전 자막을 숨기고 다음 대사를 기다린다. 같은 화면 재확인은 기존 정책인 3초 간격 최대 2회다. 외부 번역 요청을 만들지 않는다.

짧은 글자/신뢰도 하한 필터는 추가하지 않았다. 흐린 글자나 1~3글자 정상 대사를 무조건 버리는 것을 피하기 위해서다. 단 하나의 픽셀이라도 다르면 OCR을 수행한다. 잡음·그라데이션·테두리가 있는 빈 대사창은 이번 차단의 보장 범위 밖이다.

### R01: 결과 창이 자동 캡처를 막음

결과 창이 원문 영역 위에 남는 동작과, 화면 전체 영역을 고르면 결과 창을 피할 공간 없이 자동 모드가 계속 켜져 있는 동작을 수정 전 재현했다.

자동 모드의 결과 창은 창 테두리와 제목 표시줄을 포함한 크기로 원문 아래/위/옆의 빈 공간을 찾는다. 선택 모니터에 자리가 없으면 다른 모니터도 후보로 확인한다. 사용자가 창을 다시 원문 위로 끌어오면 다음 자동 확인 시 이동시키고, 그 회차 캡처를 건너뛰어 창을 옮기기 전 화면이 OCR에 들어가지 않게 한다.

빈 공간이 없으면 자동 모드를 끄고 결과 창과 주 화면에 영역 축소/창 이동 후 재시작 안내를 표시한다. 이어지는 '번역 완료' 상태가 이 안내를 지우지 않는다. 최소화된 결과 창은 가림으로 계산하지 않는다. 실제 여러 모니터·혼합 DPI 이동은 미검증이다.

### I02: 검증 설명 정정

`mouse-translation.ko.md`, `auto-translation-recovery.ko.md`의 '로컬 서버 테스트' 설명을 정정했다. translation_protocol은 준비된 JSON 응답과 요청 본문을 검사하는 단위 테스트다. 실제 HTTP 시간 초과·취소·429/456 처리 검증으로 해석하면 안 된다.

- 실제 엔진 2종에서 `はい`, `いいえ`, `OK` 정확히 보존: 6개 검사 통과.
- 흐린 한 픽셀 보존, 이미지 행 padding, 사전 검사 취소 후 늦은 결과 차단 검사 통과.
- 실제 Windows 창 겹침 이동, 공간 부족 중지/안내, 자동 모드 빈 이미지 처리 검사 통과. 표시 문구는 명시적인 테스트용 문구이며 실제 번역 결과를 가장하지 않는다.
- 기존 모델 누락 테스트 2개는 완전한 흰 이미지 대신 글자가 있는 이미지로 변경했다. 비동기 결과를 기다리며 동일한 모델/실행 파일 오류를 검증한다.
- 최초 전체 실행은 모델 누락 테스트의 빈 이미지 입력 및 동기 오류 기대 때문에 paddle_ocr 1개 실패했다. 테스트 목적에 맞게 수정 후 위 전체 결과를 얻었다.
- 빌드 스크립트는 정상 완료했다. 배포 도구의 translations catalog, DirectX compiler, VCINSTALLDIR 경고가 있으므로 '배포 경고 0'이라고 보고하지 않는다.
- 외부 DeepL 호출 0회. 실제 게임 문장 누락 해결률, 실번역 지연, 모바일 성능을 측정한 결과가 아니다.

## 다음 QA에서 필요한 항목

현재 수정에 앞서 추가 자료를 요구할 필요는 없다. 다음 현장 QA는 합성 이미지 재실행보다 아래 항목이 유용하다.

1. 실제로 문장이 누락되던 게임에서 자동 모드와 같은 정지 화면의 Ctrl+Alt+T 결과를 비교한다. 원문 누락인지 변화 감지 누락인지 구분한다. API 없이도 OCR 원문 비교 가능.
2. 텍스트 타이핑 애니메이션 중/완성 후의 문장 전체 인식과 빈 대사창 전환을 확인한다. 단색뿐 아니라 장식·그라데이션·움직이는 배경도 포함한다.
3. 마우스 올려두기 모드에서 빠르게 이동·정지·취소를 반복하고 오래된 결과 표시, 반응 지연 누적을 확인한다. R02(취소된 Paddle 작업의 계속 실행/대기)는 이번에 수정하지 않았다.
4. 100%/150% 혼합 DPI와 왼쪽 음수 좌표 보조 모니터에서 결과 창 이동/영역 좌표, 전체화면 게임 호환성을 확인한다.
5. CPU와 메모리를 장시간 측정한다. 1시간 누수 테스트는 이번에 수행하지 않았다.
6. R03/R04의 HTTP 오류 대응은 로컬 HTTP 테스트 환경을 만든 뒤 확인해야 한다. 실제 서비스에 요청 제한을 일부러 유발하지 않는다. 요청 제한 후 대기, 할당량 초과 중지는 아직 미구현이다.

Cowork 보고서에 쓰인 API 호출/문자 예산은 예시이며 사용자가 승인한 실제 호출 예산으로 간주하지 않는다.

## 공식 API 참고

- [Qt 6.8 QFutureWatcher](https://doc.qt.io/qt-6.8/qfuturewatcher.html): finished 결과를 UI 스레드에서 받고 세대 번호로 취소된 요청을 무시한다. QtConcurrent 기본 run 자체를 강제 취소한 것으로 주장하지 않는다.
- [Qt 6.8 QWidget](https://doc.qt.io/qt-6.8/qwidget.html): frameGeometry와 move를 사용해 창 테두리를 포함한 영역으로 배치한다.

시간과 메모리는 각 벤치마크 프로세스 측정값이다. 전체 앱 상시 사용량, 번역 API 지연, 모바일 성능을 뜻하지 않는다. 이번에는 언어 선택 모드만 재측정했고 다국어 13종 전체 벤치마크를 다시 돌리지는 않았다.

QA 원본 단색 이미지 4종을 배포 CLI에서 두 엔진 옵션 각각 3회씩 실행했다(24회). 모두 종료 코드 3, 빈 원문, `ocrEngine=blank-image`, `ocrAttempts=0`, 네트워크 사용 false였다. CLI 내부 OCR 및 전체 처리 시간 중앙값 각각 1ms, 최대 호스트 메모리 17.46MiB. 이 시간에는 프로세스 시작 전 구간이 포함되지 않는다.

기존 설치 폴더 `%LOCALAPPDATA%\Programs\SubtitleTranslator`를 갱신했다. 설치본 `--smoke-test` 종료 코드 0이며 배포본/설치본 실행 파일 SHA-256 일치:

`DE0680160ED5E9F2B5298F2FBB6DAC73A262BE01976AB34473E4C069DD389B15`

설치본 화면도 확인했다. T/P/H 단축키는 등록됐고 기존 M 충돌은 F8 대체 안내가 유지된다. 테스트 후 앱을 자동 번역 모드로 실행하지 않았다. 바탕 화면의 기존 바로가기는 이전처럼 `--auto`를 사용한다.
