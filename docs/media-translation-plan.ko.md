# 미디어 번역 모드 확장 기획·설계 (게임·뉴스·영화·커뮤니티)

- 작성: 2026-10-01
- 대상: subtitle-translator Windows 앱 (Qt 6.8, C++17, PaddleOCR + Tesseract, DeepL)
- 성격: 기획·설계 문서. 코드 변경 없음. 외부 사실은 2026-10-01 확인했고 [출처](#11-출처)에 정리. 수치 가운데 직접 재지 않은 것은 [추정]으로 표시

## 간단한 사전 설명

지금 앱은 "게임 대사창 한 곳을 계속 지켜보다가 바뀌면 읽어서 번역"하는 데 맞춰져 있다. 이것을 **해외 영상(게임 영상·뉴스·영화)과 글(기사·패치노트·커뮤니티 글)** 전반으로 넓히려면 입력 방식이 네 가지 필요하다.

1. **화면 자막 읽기**: 영상에 보이는 자막을 OCR로 읽음. 지금 기술을 거의 그대로 씀
2. **소리 듣기**: 자막 없는 영상의 말소리를 받아 적어(음성 인식) 번역
3. **글 번역**: 기사·커뮤니티 글처럼 긴 글을 문단째 번역
4. **파일 번역**: 영화·영상 파일의 자막 파일(.srt 등)을 통째로 번역해 새 자막 파일로 저장

추천 순서는 **영상 자막 모드 → 자막 파일 모드 → 글 모드 → 음성 모드**다. 앞의 셋은 지금 코드(OCR·DeepL·화면 자막)를 대부분 재사용하고, 음성 모드만 새 엔진(Whisper)과 오디오 캡처가 필요해 가장 크다.

꼭 알아둘 제약이 세 가지 있다.

- **넷플릭스 같은 유료 스트리밍은 화면과 소리 모두 캡처가 막힌다(DRM).** 검은 화면·무음이 정상 동작이며 우회하지 않는다.
- **DeepL API 요금제가 2026년 7월에 바뀌었다.** 신규 무료 요금제는 매달 초기화되지 않는다. 영화·음성처럼 양이 많은 모드는 사용량 표시가 필수다.
- 유튜브의 남의 영상 자막은 공식 API로 받을 수 없다. 화면 자막 OCR이나 음성 인식을 써야 한다.

## 3. 모드별 설계

### 3-1. 영상 자막 모드 (1순위)

**용도**: 유튜브·트위치·뉴스 영상, 게임 트레일러의 화면 자막(하드 자막, 유튜브 CC 포함) 번역.

**지금 게임 모드와 다른 점**

| 항목 | 게임 대사창 | 영상 자막 | 설계 |
|---|---|---|---|
| 자막 지속 시간 | 길다 (사용자가 넘길 때까지) | 1–4초 | 감지 주기 0.4초 → 0.2–0.25초, 안정 판정 2회 → 1회 |
| 배경 | 대사창이라 거의 고정 | 영상이 계속 움직임 | 영역을 자막 띠로 좁게. "강제 읽기 3초"를 자막 띠의 글자 부분 변화로 판정 |
| 위치 | 게임마다 다름 | 대개 화면 아래 15–20% | "영상 하단 자막" 영역 프리셋 + 플레이어 창 자동 맞춤(선택) |
| 번역 표시 | 원문 아래 | 원문을 가리는 편이 보기 좋음 | 배치 옵션 "원문 위에 덮기"(반투명 배경) 추가 |
| 지난 자막 | 필요 적음 | 놓친 자막 다시 보기 필요 | 최근 자막 기록 창 (원문/번역, 시각) + 텍스트·SRT로 저장 |
| 일시정지 | — | 영상 정지 시 같은 자막 유지 | 같은 원문은 재번역 안 함 (이미 있음) |

**자기 창 캡처 문제 해결**: 영상 영역을 크게 잡으면 앱의 자막·결과 창이 캡처에 섞인다. 이번 QA에서 수정본은 자동 번역을 멈추는 방식으로 막았다(A-04 통과). 영상 모드는 그보다 나은 방법으로 Windows `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`를 자막·결과 창에 걸어 **화면에는 보이지만 캡처에는 안 잡히게** 한다(Windows 10 2004 이상). Qt `grabWindow` 경로에서도 제외되는지는 시험이 필요하다 [미검증].

**속도 목표** [추정]: 자막이 바뀌고 번역이 화면에 뜰 때까지 1.5초 이내. 지금 측정값은 OCR까지 중앙값 1.19초(게임 모드), DeepL 1.1–1.6초라서 그대로면 2.5–3초다. 감지 단축(−0.4초), 자막 띠 크기 축소(OCR 시간 단축)를 하고, 번역은 바로 다음 자막까지 화면에 유지해 늦게 와도 읽을 수 있게 한다.

**알려진 위험**

- 유튜브 자동 생성 자막은 단어 단위로 한 글자씩 올라온다 → 타자기 효과와 같다. 지금 코드의 "완성될 때까지 기다림"이 그대로 통한다(C-07 재실행 5/5).
- 자막에 테두리·반투명 배경 띠가 있으면 빈 자막 구간에 가짜 글자가 나올 수 있다(QA 결함 D-05). `docs/qa-hardening-completion-2026-10-01.ko.md`에서 단색·테두리·액자 입력은 수정·검증됐지만 **잡음 배경 오인식은 남아 있다**. 움직이는 영상 배경에서 다시 측정해야 한다.
- 유튜브는 자체 "자동 번역" 자막(설정 → 자막 → 자동 번역)을 이미 제공한다. 이 모드의 가치는 **DeepL 품질, 하드 자막, 유튜브 외 사이트**에 있다는 점을 안내에 쓴다.

### 3-2. 자막 파일 모드 (2순위)

**용도**: 소장한 영화·드라마·영상 파일의 자막 파일(.srt, .vtt, .ass) 일괄 번역. 화면 캡처를 안 하므로 DRM과 무관하고, 가장 정확하며 한 번 번역하면 끝이다.

**흐름**

1. 자막 파일 열기 (또는 영상 파일 옆 같은 이름의 자막 자동 탐지)
2. 미리 계산: 줄 수, 글자 수, 예상 DeepL 사용량 표시 → 사용자가 확인
3. 줄을 문맥 단위로 묶어(여러 줄에 걸친 한 문장 합치기) 50조각씩 요청
4. 타이밍은 그대로 두고 글자만 바꾼 새 파일 저장: `영화.ko.srt` (원본 덮어쓰기 금지)
5. 선택: 원문+번역 두 줄 자막

**설계 요점**

- 자막 해석·저장은 공통 코어(C++)에 둔다: `.srt`/`.vtt`는 단순, `.ass`는 스타일 태그(`{\i1}` 등)를 보존하고 글자만 교체
- 이미 번역 언어인 줄은 지금 규칙대로 건너뜀
- 중간 실패 시 이어서 하기(번역된 줄 캐시)
- 영상 안에 들어 있는 자막(mkv 내장)은 ffmpeg로 추출해야 한다 → 2단계에서는 "자막 파일만", 내장 자막 추출은 이후 선택 기능

**사용량 예** [추정]: 2시간 영화 자막 1,200–1,800줄 × 평균 30–40자 ≈ 4–7만 자. 아래 요금제 기준 Developer 무료 100만 자로 영화 15–25편.

### 3-3. 글 모드 (기사·패치노트·커뮤니티 글, 3순위)

**용도**: 해외 게임·뉴스 기사, 패치노트, Reddit·X 글.

**입력 세 가지**

| 입력 | 방법 | 장점 | 단점 |
|---|---|---|---|
| 클립보드 (기본) | 글을 복사하고 `Ctrl+Alt+C`(제안) → 결과 창에 번역 | OCR 오류 없음, 가장 정확 | 복사 한 단계 필요 |
| 화면 영역 OCR | 기사 영역 드래그 → 문단 순서대로 읽기 | 복사가 막힌 페이지·이미지 글 | 긴 글은 OCR 오류·시간 증가 |
| 스크롤 연속 읽기 | 영역 고정 후 스크롤하면 새로 보인 부분만 추가 | 긴 기사 | 구현 난도 높음 → 후순위 |

**설계 요점**

- 문단을 유지한 채 나눠 보내기: DeepL 한 요청 50조각, 공통 코어 원문 32KB 제한 → 문단 단위로 쪼개 순서대로 이어 붙임
- 결과 창을 "원문/번역 나란히" 보기로 확장, 문단 클릭 시 서로 강조
- 커뮤니티 글 프리셋: 짧은 글, 줄바꿈·이모지·@멘션·해시태그·링크는 번역하지 않고 보존
- 게임 용어 보존: 사용자 용어집(예: "Patch Notes"→"패치 노트", 캐릭터 이름은 그대로). DeepL 용어집 기능 또는 앱 내부 치환표 (4-3)

### 3-4. 음성 모드 (4순위, 가장 큼)

**용도**: 자막 없는 해외 뉴스·인터뷰·게임 영상의 말소리를 실시간 자막으로.

**처리 흐름**

```text
[PC 소리 출력] --WASAPI 루프백--> [16kHz 모노 변환] --> [말 구간 감지(VAD)]
   --> [Whisper 음성 인식 (로컬)] --> [문장 단위로 묶기] --> [DeepL] --> [화면 자막·기록]
```

- **소리 받기**: Windows WASAPI 루프백(스피커로 나가는 소리를 그대로 받음). 공유 모드만 지원. **DRM 보호 오디오는 캡처되지 않는다**(Microsoft 문서 명시).
- **음성 인식**: whisper.cpp (MIT 라이선스, C++이라 이 앱과 같은 언어). 모델 크기는 아래와 같고, 앱에는 small 또는 large-v3-turbo 양자화본을 권장 [추정, 실측 필요].

| 모델 | 크기 | 용도 |
|---|---|---|
| base-q5_1 | 57 MiB | 저사양 PC, 정확도 낮음 |
| small-q5_1 | 181 MiB | CPU 기본값 후보 |
| large-v3-turbo-q5_0 | 547 MiB | GPU(CUDA·Vulkan) 있을 때 권장 |
| large-v3 | 2.9 GiB | 배포에는 너무 큼 |

- **지연** [추정]: 말 구간을 끊어 처리하므로 말이 끝나고 2–5초 뒤 번역. "실시간 동시통역"이 아니라 "몇 초 늦은 자막"으로 안내
- **원문 언어**: Whisper가 자동 감지하지만, 사용자가 고르면 더 정확·빠름
- **이미 있는 대안과 비교**: Windows 11 "라이브 캡션"의 실시간 번역은 Copilot+ PC에서만 지원한다. 이 앱은 일반 PC + DeepL 품질이 차별점
- **파생 기능**: 영상 파일의 소리를 Whisper로 받아 적어 `.srt` 생성 → 3-2 자막 파일 모드로 번역 (자막 없는 소장 영상용). ffmpeg 필요

**배포 부담**: 모델이 커서 설치본에 넣지 않고 "음성 모드 처음 켤 때 내려받기"로 한다. 지금 PaddleOCR 모델 준비 스크립트(`scripts/prepare-paddle-models.ps1`)와 같은 방식의 확인 절차(해시 검사)를 쓴다.

## 4. 공통 기반 변경

### 4-1. 모드 구조

`MainWindow` 한 클래스(1,069줄)에 모든 기능이 들어 있어, 모드를 늘리기 전에 나눈다.

```text
MainWindow (화면 틀, 단축키, 모드 전환)
 ├─ ModeProfile        모드별 설정 묶음 (영역, 감지 주기·안정 횟수, 자막 배치, 용어집, 원문 언어)
 ├─ ScreenTextSource   화면 캡처 + 바뀜 감지 + OCR       ← 게임 / 영상 자막 / 글(OCR)
 ├─ ClipboardSource    클립보드 글                       ← 글
 ├─ SubtitleFileSource 자막 파일 읽기·쓰기 (코어)         ← 자막 파일
 ├─ AudioSource        WASAPI + VAD + Whisper            ← 음성
 ├─ TranslationQueue   조각 나누기, 50개 단위 요청, 캐시, 사용량 집계
 └─ Presenters         화면 자막 / 결과 창(나란히 보기) / 기록 창
```

- 모드는 "입력(Source) + 표시(Presenter) + 설정(Profile)"의 조합으로 정의한다. 새 모드는 이 세 가지를 고르는 것으로 추가
- 한 번에 한 모드만 실행. 모드 전환 시 이전 작업 취소(지금 `cancel()` 규칙 유지)
- 설정 저장 위치: 지금 레지스트리 `HKCU\Software\PersonalTools\SubtitleTranslator` 아래 `modes/<이름>/...`

### 4-2. 기록과 내보내기

모든 모드에서 "원문 · 번역 · 시각 · 모드"를 세션 기록으로 남기고, 텍스트·SRT로 저장할 수 있게 한다. 영상 자막 모드에서는 화면 기록 시각으로 간이 SRT를 만들 수 있다. 기록은 로컬에만 저장하고 기본값은 "앱 종료 시 삭제"로 둔다.

### 4-3. 용어집

- 게임 이름·캐릭터 이름·고유명사가 엉뚱하게 번역되는 문제를 줄인다
- 1차: 앱 내부 치환표(번역 전 보호 → 번역 후 복원). DeepL 요청에 영향 없음
- 2차: DeepL 용어집 API 연동(언어 쌍 지원 범위 확인 후)
- 모드별·게임별 용어집 파일(CSV)로 가져오기·내보내기

### 4-4. 사용량·비용 표시

양이 많은 모드가 생기므로 필수다.

- 번역 전에 예상 글자 수 표시 (자막 파일·긴 글)
- 이번 세션·이번 달 누적 글자 수, `GET /v2/usage`(이미 구현된 `checkUsage`)로 남은 양 표시
- 사용자가 정한 상한(예: 세션당 5만 자)에 닿으면 자동 번역 멈춤
- 지금 QA에서 확인한 대로, 같은 원문은 다시 보내지 않음(이미 있음). 403/429/456 응답 시 자동 번역 중지도 이미 들어가 있음(`docs/qa-hardening-completion-2026-10-01.ko.md`)

### 4-5. 번역 엔진 선택 (선택 사항)

DeepL만 쓰면 요금제 변경의 영향을 그대로 받는다. `TranslationService`를 인터페이스로 바꿔 두면 나중에 다른 엔진(다른 번역 API, 로컬 번역 모델)을 붙일 수 있다. 이번 범위에서는 **구조만 열어 두고 DeepL만 구현**한다.

## 6. 비용 (DeepL API, 2026-10-01 기준)

DeepL API 요금제가 2026년 7월에 바뀌었다. 기존 API Free·Pro는 새로 가입할 수 없고, 새 요금제는 아래와 같다고 소개된다. 실제 가격은 DeepL 가입 화면에서 지역별로 다르게 나오므로 확인이 필요하다.

| 요금제 | 포함 글자 | 비고 |
|---|---|---|
| Developer (무료) | 총 100만 자, **매달 초기화 안 됨** | 개발·평가용 |
| Growth | 월 100만 자 (연 1,200만 자) | 초과분 과금 |
| 기존 Free·Pro 키 | 계속 사용 가능 여부 확인 필요 [미검증] | 사용자 키가 어느 요금제인지 확인 |

**모드별 사용량 예** [추정]

| 사용 | 글자 수 |
|---|---|
| 게임 1시간 (대사 300줄 × 40자) | 약 1.2만 |
| 유튜브 영상 10분 (자막 150줄 × 35자) | 약 5천 |
| 영화 1편 자막 파일 | 4–7만 |
| 뉴스 음성 1시간 (분당 약 150단어) | 약 5만 |
| 기사 1편 (1,500단어) | 약 9천 |

음성 모드를 하루 1시간씩 쓰면 한 달 150만 자 정도라 Growth의 월 포함량을 넘는다. **음성 모드는 사용량 상한(4-4)이 반드시 같이 들어가야 한다.**

## 9. 위험과 정할 것

| 위험 | 영향 | 대응 |
|---|---|---|
| 영상 자막이 짧아 OCR+번역이 따라가지 못함 | 자막 누락 | 1단계 완료 기준으로 측정. 못 미치면 "기록 창에서 다시 보기"를 주 사용 방식으로 |
| Whisper가 CPU에서 느림 | 음성 모드 지연 증가 | small 모델 기본, GPU 감지 시 turbo. 실측 후 결정 |
| DeepL 요금제 변경 | 사용량 많은 모드에서 비용 | 사용량 표시·상한(4-4), 엔진 교체 구조(4-5) |
| 앱 크기 증가 | 설치 부담 | 음성 모델은 선택 내려받기 |
| 저작권 | 배포·공유 시 문제 | 개인용, 크롤링·공유 기능 없음 |
| `MainWindow` 분리 중 회귀 | 기존 게임 기능 고장 | 0단계에서 이번 QA 도구(suite-app)로 회귀 시험 |

**사용자가 정할 것**

1. 음성 모드를 4단계로 둘지, 수요가 크면 2단계로 당길지
2. 사용 중인 DeepL 키가 기존 Free/Pro인지 새 Developer/Growth인지 (월 사용 한도 판단)
3. 기록 저장 기본값 (종료 시 삭제 / 보관)
4. 모드 전환 단축키 배치 (`Ctrl+Alt+1~4` 등)
